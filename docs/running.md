# Running and verifying CausalPacket

The [README](../README.md) contains the quickest setup. These notes cover
alternate launch methods, the CLI, and verification without starting servers.

## Prerequisites and setup

Use Linux or WSL, Python 3.12+, Node.js 20.9+, and pnpm. The worker uses Unix
resource controls; native Windows is not a verified runtime. Setup needs access
to package registries; analysis needs no external API or network capture access.

```bash
./run.sh setup
./run.sh dev
```

Setup creates `.venv-hardened`, installs pinned Python dependencies, regenerates
synthetic captures and installs frontend dependencies from the frozen lockfile.
The launcher starts one server pair and stops its own process groups on Ctrl+C.
It refuses occupied ports rather than killing an unrelated process.

If Python 3.12+ is not found automatically, select an installed interpreter:

```bash
CAUSALPACKET_PYTHON=/absolute/path/to/python3.12 ./run.sh setup
```

`CAUSALPACKET_WHEELHOUSE` optionally selects a local directory of verified wheels
for offline Python installation. `./run.sh setup --backend-only` leaves frontend
installation to a separate workflow. Use `.venv-hardened` as the verified environment.

## Separate terminals

```bash
# Terminal 1: backend
./run.sh api

# Terminal 2: frontend
cd frontend
pnpm dev
```

- Interface: <http://localhost:3000>
- API health: <http://127.0.0.1:8000/api/health>
- API documentation: <http://127.0.0.1:8000/docs>

The default frontend uses `http://127.0.0.1:8000`. Its optional
`NEXT_PUBLIC_API_BASE_URL` setting is documented in
[the frontend environment example](../frontend/.env.local.example).
The backend allows only localhost/127.0.0.1 origins on port 3000 in its default
configuration, in both CORS and request validation. Changing the frontend URL
alone does not configure public hosting. Set `CAUSALPACKET_ALLOWED_ORIGINS` on
the backend to configure both layers; see [deployment.md](deployment.md).

Stop both terminals when finished. The API reload watcher is restricted to
`backend/`. Keep one backend process: metadata sessions live in process memory.

## CLI

From the repository root:

```bash
./run.sh cli samples/05_mixed_scan_and_fault.pcap
./run.sh cli samples/03_possible_scan.pcap --json
./run.sh cli samples/04_gateway_transition.pcap --context samples/gateway-baseline.json --markdown
```

Context follows `NetworkContext` in [the API contract](api-contract.md).
The CLI and API use the same supervised analysis engine.

## Checks and samples

```bash
./run.sh doctor
./run.sh check
./run.sh verify-demo --output .artifacts/demo-verification.json
./run.sh samples
```

`check` runs backend tests, fixture contracts, frontend typechecking and the
production build. `verify-demo` exercises real generated bytes through ASGI and
isolated workers without opening HTTP sockets or starting browser/server tasks.
It checks all nine samples, gateway baseline/approval/reset invariants, exports,
and malformed-upload recovery. It is not a browser test.

If a restricted environment blocks Turbopack's internal worker socket, the
supported alternate build is:

```bash
cd frontend
node node_modules/next/dist/bin/next build --webpack
```

This does not disable TypeScript checking. Record failed commands and successful
fallbacks honestly. Measurements and browser-verification provenance are in
[evaluation.md](evaluation.md).

## Optional frontend interaction checks

These checks use React Test Renderer 19.3.1 with the application's React version.
The extra test packages live outside the project; they are not app dependencies.
Prepare actual API/worker responses, then exercise the component state and race
guards without HTTP sockets or a browser:

```bash
mkdir -p /tmp/causalpacket-ui-check
pnpm add --dir /tmp/causalpacket-ui-check react@19.3.1 react-test-renderer@19.3.1 --ignore-scripts
.venv-hardened/bin/python -m scripts.prepare_ui_checks
CAUSALPACKET_REACT_TEST_RENDERER=/tmp/causalpacket-ui-check/node_modules/react-test-renderer node scripts/verify_frontend.cjs
```

The component test transport is stubbed with actual ASGI/worker results. It checks
lab/main-report separation, source-frame mapping, errors, stale source/context/
mode responses and exports. It does not establish CSS layout, real browser
downloads or actual HTTP connectivity.

For the real browser walkthrough, install Playwright 1.63.0 and its Chromium
browser in a separate tool directory, start one API/UI pair, and run:

```bash
CAUSALPACKET_PLAYWRIGHT_MODULE=/absolute/path/to/playwright node scripts/verify_browser.cjs
```

Normal analysis and lab requests use the live API; the script explicitly
intercepts the delayed-response fault-injection case. Screenshots/downloads go
under `.artifacts/final-ui/`. The script closes its browser; stop your server
launcher afterward. In restricted environments, server binding or browser
launch can be blocked even when compilation and component checks pass.

## Source snapshot

```bash
./run.sh package
```

The archive is `.artifacts/causalpacket-submission.tar.gz`, with a per-file SHA256
manifest. Environments, dependency trees, caches, Git metadata, private env files,
and undeclared captures are excluded. Included samples must match deterministic
regeneration. Credential-pattern checks are scoped checks, not proof that every
possible secret is absent.

Rebuild after final edits. Extract into a clean writable directory when preparing
a repository; the archive itself is not publication or organizer submission.
